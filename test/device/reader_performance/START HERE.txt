XTEINK X4 PRO   |   CROSSINK READER HARDWARE TEST

Use your existing card. Everything under “SD card” belongs at the card’s top level. Keep “Results.html”, “Reference images”, and this guide on your Mac. Start with card preparation, run steps 1–4 on A then B, and finish with the visual and restore checks. For a complete comparison, do the visual steps on A before switching and repeat on B. One reader, one card and identical settings make the results comparable.

WHAT TO KEEP
• CrossInk-Test/X4PRO-INDEX-RESULTS.txt contains automatic microsecond timings from actual book opens and page rendering. The first line in the supplied file is only a heading. Both test builds append while you read the supplied books.
• Open Results.html on your Mac, select a COPY of the timing file, fill out the observations, then click “Save hardware observations”. Keep the raw file and X4PRO-HARDWARE-NOTES.txt together with any photos. The worksheet works offline and requires no installation. Save before closing it.
• The optional CrossPoint PR #8 kit writes a different file at the ROOT of the card, also called X4PRO-INDEX-RESULTS.txt. Its separate workflow is at the end.

PREPARE THE EXISTING CARD
1. Have the X4 Pro application .bin for the CrossInk firmware you normally use available on your Mac. The supplied Restore-crossink-x4pro-13fef267.bin is the clean build of stack PR #6. Use it for restore only if that is the version you want back. Record your firmware and panel details from About if available. Charge the reader before changing firmware.
2. Power the reader off completely. Insert the card in your Mac. In Finder press Command–Shift–period to show hidden files. Copy the entire .crosspoint folder to a dated folder on your Mac and verify the copy contains your files. On the CARD rename .crosspoint to .crosspoint-before-test. If that name already exists, stop and identify the earlier backup; give this run its own distinct name and keep a note. Leave your books, fonts and other folders where they are. If the card has no .crosspoint folder, record that and skip restoring it later.
   Two other existing items can receive writes during these checks. Copy the hidden .crossink-stats-backup folder and the root file “My Clippings.txt” to your dated Mac backup if present. On the card rename the originals to .crossink-stats-backup-before-test and “My Clippings-before-test.txt”. Choose unused names and write them down. Sleep can make a daily stats backup, and the clipping test can append to the text export. If either item was absent originally, simply record that.
3. Copy the CONTENTS of “SD card” to the top level of the card. You should see CrossInk-Test/Books/A, CrossInk-Test/Books/B, CrossInk-Test/X4PRO-INDEX-RESULTS.txt and the clearly named .bin files. Also copy your usual firmware if different. For the optional bitmap-font check, follow the Mac-side “Optional SD font/Font notes.txt” to add the included TestFamily folder inside /fonts. If a prior CrossInk-Test folder exists, archive it intact first. Never merge the empty timing file into a previous run. Optional Mac integrity check: from the unzipped kit folder run “shasum -a 256 -c SHA256.txt”.
4. Eject the card in Finder and put it back in the powered-off reader. Boot. The test session uses a fresh .crosspoint. In Settings > System > SD Card Firmware Update select A-crossink-x4pro-stack-test.bin and confirm the exact filename. Keep the device powered until it restarts. Use the same menu to install B-crossink-x4pro-reviewed-test.bin when A is done. The core A/B and optical tests need no network or USB serial connection.

1. MAKE THE TWO RUNS COMPARABLE
Use File Browser to open /CrossInk-Test/Books/A for firmware A, and /CrossInk-Test/Books/B for B. Each contains the same bytes. Trial-1, Trial-2 and Trial-3 have distinct paths so each can build a fresh index without clearing anything. Use File Browser directly; a library cover scan can pre-build EPUB metadata. If you see only “epub-warm” for a trial, record it as warm. For another cold attempt, use a fresh, previously unopened trial or a fresh test session. Reopening one copy three times gives one cold sample.

For a quick check before a long session, open Trial-1/Numbered.txt and turn one page. Power down safely, inspect the timing file on the Mac and look for an A,txt-index row and A,txt-paint rows below the heading. Keep that report and cache. Resume the trial; its first-open timing is already saved.

Record font/size, spacing, ruling, anti-aliasing, Text Darkness, orientation, refresh frequency, top/bottom bars, frontlight, approximate ambient temperature, device/panel, card, and run order. Keep the calibration fixed for the timed runs. Suggested repeatable starting point: built-in font, default spacing, portrait, Text Anti-Aliasing on, Ruled Lines off, Refresh Frequency 5 pages. Let each turn settle. Do the experimental settings changes only after the three timed trials. Restore starting settings before switching builds.

2. INDEX TIME, PAINT TIME AND TXT PROGRESS
In each Trial folder, open Numbered.txt, wait for page one, turn forward three pages, then one back. Note the page count and first numbered line on the same page in A and B. Exit to File Browser, reopen and confirm your position. Repeat for all three trials on each build. Every Numbered.txt has 1,000 numbered lines, CRLF, and no final newline. It can take noticeably longer to open on A. Leave the device running while the indexing message is visible.

After the timed trials, on Trial-1 mark a unique middle line. Go forward once, immediately change font size or orientation, then sleep, wake and reopen. The new layout should still contain your recently read passage; page numbers may change. Repeat with a non-default Character Spacing and Ruled Lines. Repeat using the supplied TestFamily at size 14 or your own installed SD bitmap font. Compare the page count, boundary lines and reopen behavior across the same font/settings on A and B. Record whether any text disappears at an edge or a line is repeated/skipped across a boundary. Try a rapid forward/back pair and return Home via the normal controls. Home and the reader should agree about progress.

3. TXT BOUNDARY CASES
Open Visual/Boundaries.txt. Check the blank paragraph, indented line, accented/combining text and mixed writing directions with a font that has those glyphs. At the end of the long unbroken word you should reach “AFTER THE LONG WORD” and “Last anchored paragraph. No terminal newline.” Try the book in portrait and landscape. With centered or right-aligned mixed text and an SD font if available, sleep using Page Overlay and compare the reconstructed page to the awake page. Open Visual/Utf8-window.txt and turn to the final “WINDOW END / COMPLETE.” The leading test data contains invisible three-byte variation selectors; a nearly blank page is expected. Reopen at the marker and go back and forward once. Open Visual/Empty.txt: expect the empty-file message; use Back and open Numbered.txt again. Record font fallbacks separately from missing words or a stuck reader.

4. EPUB FIRST OPEN, TABLE OF CONTENTS, CLIPPING AND WARM OPEN
For both Spine-299.epub and Spine-300.epub in EACH trial: open from File Browser, wait for the first chapter, turn forward and back, close, then reopen and wait for the page to settle. These books have 299 and 300 spine positions, reverse-order chapter links, and a repeated occurrence of chapter 002. The cold and warm operations are measured separately. On Trial-1, open Select Chapter (on X4 Pro, swipe up, tap the more menu •••, then Select Chapter). Choose “Far anchor” (near the end of Chapter 002), then “Near anchor” (its beginning), then the highest numbered chapter (298 or 299). The chapter selector may open near its bottom. Moving Down from the last entry wraps to the two named anchors at the top. Check the heading and passage on the page; a chapter-level status slot can retain the first TOC label for the entire spine item. Check for “Copper lantern”, “Chapter 002”, and the selected chapter marker respectively. Go back to Chapter 001 and create a clipping of the sentence below across a wrapped line. Compare every word, separator and final period in the saved clipping.

The small red fox crossed the old stone bridge before sunrise.

Open Visual/Typography.epub and clip the same sentence across both italic and bold words. Check the underline, thin rule, accented letters, Japanese ruby, RTL numbers, and two separate numbered list items. Close and reopen after turning a page to exercise cached styled text. Use the same fonts and compare A with B, especially for scripts that require an SD font. Repeat the first-page checks with Text Anti-Aliasing off and on, then once in dark mode if you use it. Check thin glyph strokes, punctuation, underlines/rules where present, a scope change into/out of a menu, and the first page after sleep. Return to the standard settings.

5. UPDATE WITH AN EXISTING CACHE
Before leaving A, save and write down a uniquely numbered line in A/Trial-1/Numbered.txt and a passage/anchor in A/Trial-1/Spine-299.epub. Also open A/Visual/Utf8-window.txt once on A to create its old index. While running B, deliberately reopen the same numbered TXT and EPUB in the A directory, using the same layout settings. Confirm the saved passages are visible, and that next/previous and an EPUB TOC jump work. The worksheet excludes these crossed A/B paths from the timing comparisons. Open the A copy of Utf8-window.txt on B, reach its final marker, then reopen it once more. Use B paths again for the other cases.

6. FOUR-TONE AND BLACK-AND-WHITE XTCH PAGES
Open Visual/Panel.xtch. Compare the five pages with the PNGs in “Reference images” on the Mac. Page 1 has black, dark gray, light gray and white bars from left to right. Page 2 is binary, with a black rectangle at left. Page 3 clears the rectangle. Page 4 is deliberately 319 × 417, with corner markers, a border and four shades. Page 5 is full size again. Look for swapped gray levels, missing edge pixels, leftover content outside the smaller page, mirrored coordinates, missing flashes or an extra flash on every binary turn. Repeat 1 → 2 → 3 → 4 → 5 and back. Check portrait, inverted portrait and one landscape orientation that the UI offers. In landscape the image may be clipped to the viewport; compare the common visible region with A in the same orientation.

Try with XTC status bars hidden and then configured to show text/icons. Check that the dark text/icons remain legible across gray bands, and re-open the menu then dismiss it to check for stale rectangles. Leave the bars hidden for the optical measurements.

7. VARIABLE-SIZE MONOCHROME, SLEEP AND A DAMAGED TEST PAGE
Open Visual/Mixed-mono.xtc. Page 1 is full size, page 2 is a smaller odd-width page, and page 3 returns to full size. On B both interior pages should be complete, with the last row/column and corner marks intact in portrait. Select Sleep Screen → Page Overlay to show the current reading page. Sleep on page 2, wake, turn to page 3, sleep and wake again. Compare to the corresponding awake page; check the area outside the small page for remnants. Restore the original sleep option.
On B only, open Visual/Damaged-page-2.xtc. Page 1 is valid. Go to page 2 and expect a load-error screen, then Back and reopen the healthy Mixed-mono.xtc. The diagnostic file deliberately has inconsistent dimensions on the second page. Leave the SD card inserted for this check.

8. PALETTE, RESIZING AND OPTIMIZED EPUB IMAGES
Open Visual/Palette.bmp in File Browser. It uses the firmware’s packed 2-bit palette and an odd-width last byte. Compare the geometry and both borders with Optimized-chart.png. Record how many distinct swatches the standalone viewer shows on each build. Its grayscale upgrade depends on the panel’s absolute-grayscale capability; a monochrome preview can merge swatches. Use Panel.xtch to judge four-tone separation. Open Visual/Truecolor.bmp, a 1,103 × 859 RGB source that must be resized; compare the composition with Truecolor.png, especially the gradient and thin lines. Native screen dithering is expected. Close and reopen both. If you use a custom sleep image, select the test BMP using the image menu, compare the sleep screen, then restore your test settings.
Open Visual/Optimized.epub and Visual/Damaged-sidecar.epub. Both should show the same four-tone chart; the latter retains a valid original PNG when its optional optimized image cannot be used. Reopen and rotate to change the available size. Compare borders, polarity, cropping and tones. In the Mac copy of the disposable cache, the intact book should have a published img_*.pxc after rendering; include a screenshot or photo if either book loses its image.

9. PERIODIC CLEANUP AND RECOVERY
On a text book, set Refresh Frequency to 5. Make at least 12 sequential single turns, including a return across a cleanup boundary, and note where stronger refreshes occur. Repeat with Refresh Frequency 1, run Refresh Screen manually, enter and leave the reading menu, then sleep/wake. Repeat a short sequence with Text Anti-Aliasing off. Inspect gray shadows of the preceding page, heavy text before/after gray settles, missing glyphs and faded status bars. Some Pro controller revisions combine refresh phases. Record what happened; visible flash counts and waveforms can differ by device and content.

10. MEASURE PANEL GHOSTING AND TAP-TO-SETTLE
Keep the reader flat and the camera fixed. Lock focus/exposure and frontlight, use identical room lighting, and turn off auto orientation. Use a longer refresh interval (e.g. 30), bars hidden and portrait. Start each repetition with the same manual cleanup on page 1 and let the panel settle. On Panel.xtch, turn to page 2, then page 3. Take a fixed-exposure photograph of page 3 at the same delay (e.g. two seconds) after each turn; repeat five times per build. Photograph page 3 after a manual refresh as a control. Save files like A-ghost-01 and B-ghost-01. Phone screenshots or simulator captures cannot measure residual pigment.

Optional numeric comparison: sample the average brightness in equal, small, unmarked squares of the photographed *panel*, measured from its upper-left corner. The old black rectangle was centered near (25%, 52%). The never-inked control is near (75%, 52%). The permanent black/white reference patches are near (10%, 12%) and (90%, 12%). Residual percent = 100 × (control − former rectangle) / (white patch − black patch). Use the same regions in both builds. Keep negative values. If white and black read identically the measurement is unusable. Report the median and spread of all five runs. An uneven light gradient shows up in the manual-refresh control too; use that to interpret any apparent difference.

For visible latency, film at a known frame rate, ideally 120 fps or higher. Count from the frame showing button depression/touch to the last visibly changing panel frame. Milliseconds = 1000 × frames / camera fps. Time at least five same-direction turns per build in the same book at the same refresh phase; record ordinary and cleanup turns separately. Keep all samples. Use the trial checkboxes in Results.html to exclude a failed or interrupted first open from the indexing comparison and record why. Camera exposure, temperature and panel revision affect results.

11. SAVE RESULTS AND RESTORE YOUR READER
Power off; copy CrossInk-Test/X4PRO-INDEX-RESULTS.txt to your Mac. Keep the photos and worksheet export. The raw txt-paint measures the paint/display call, txt-index measures building a missing TXT index, epub-cold/warm measures the foreground EPUB metadata load, epub-render covers a render invocation, xtc-paint and image-paint cover their respective draw calls. The page field is zero-based; epub-render reports the spine index. Error and menu-related invocations may also appear in raw rendering rows. Timestamping ends before the result is written to the card. It cannot measure when physical pigment finishes settling. An empty file means no matching operations were recorded; check the test firmware, folder path and supplied timing header.

With the test .crosspoint STILL active, reinstall your usual X4 Pro CrossInk .bin from Settings > System > SD Card Firmware Update. Wait for it to restart fully. THEN power off, insert the card in the Mac, and rename the newly created .crosspoint to .crosspoint-test (choose another unused suffix if necessary). Rename .crosspoint-before-test back to .crosspoint. Also archive the test-created .crossink-stats-backup and “My Clippings.txt” under unused names or move them to your dated Mac test folder. Rename .crossink-stats-backup-before-test back to .crossink-stats-backup and “My Clippings-before-test.txt” back to “My Clippings.txt” for items that existed before. Verify all original names are back. Eject in Finder and boot. Check your original settings and a familiar book’s reading position. Keep the backup on the Mac. You may move CrossInk-Test and test firmware files off the card after verifying restoration.

OPTIONAL — THE SEPARATE PRESERVE-WORD-SPACING WORKSPACE KIT
The original “CrossPoint PR #8” ZIP is included separately on the Mac side. It tests the paragraph/list position lookup with 12 alternating timed pairs for each of eight cases. Run it only if you also want that measurement, while your original .crosspoint remains set aside. Unzip it on your Mac and use its “Read me first.txt” instructions with this isolated card. Its marker and firmware belong at the card ROOT; keep an existing root result or .tmp file by moving it to a dated Mac folder before a fresh run. The CrossPoint test runs at boot and writes its own root /X4PRO-INDEX-RESULTS.txt. Save this as a separate Mac copy under a folder such as PR8-Lookup. Use the normal restore order in step 11 after the final diagnostic run.
